# Review: Plan 3 Task 40 (foldable phones), first review, 2026-10-29

Branch `origin/wip/lead-p3-task40` @012aafc (main line 6b4c590 already merged; trial merge of the current main line said "Already up to date"). Read-only reviewer. Detached worktree `~/x2f-worktrees/rv-t40` (now removed).

## Verdict: CHANGES REQUIRED (3 Important, 6 Minor, plus a scope note)

The core is right. One app-shell tree for every layout means folding, unfolding and crossing 1000 px no longer remount the route. The old code remounted the whole Outlet at 1024 px, which restarted the room's escrow; this change fixes that. `useTradeEscrow` stays in `ReadyRoom` (key = code), above `Panes`. The `Panes` slots keep their index (null placeholders), so `main` never remounts. TradeGlance's amounts come only from the device's escrow (`deviceTotal`, `escrow.amountAtomic`). The segment emulation is real: every hinge test ran and passed, and none skipped. Three problems need fixing before landing: the cover layout can hide the security alert, the cover layout can switch on for ordinary phones and windows, and at 600–999 px sheets only cover the left half of the screen.

## Important

**I1. The flip cover layout hides the integrity / mismatch alert and shows a blank screen.**
- Code: `apps/web/src/screens/trade/TradeRoom.tsx:276` passes `glance={broken ? null : …}`, and `apps/web/src/styles/fold.css:158` hides `[data-pane='main']` (`display: none`) in `cover` whether or not a glance exists.
- Scenario: the escrow reports `participants-mismatch` and the viewport is 360x380. The probe showed "Security check failed. Don't fund this trade. …" at 390x844 and an empty `<main>` (innerText `""`) at 360x380.
- The cover card also never shows the device's own warnings. It shows the API's escrow chip ("Escrow secured", `TradeGlance.tsx:18`), while the main pane, now hidden, says "The escrow stopped on this device. Don't send any money until it runs again."
- Fix:
  - when `broken`, render the integrity screen as the glance, or skip the cover rule;
  - the glance should show the escrow's stopped/refusal sentence (`stoppedText` / `refusalText`) instead of, or next to, the API chip;
  - add an e2e test: cover + `participants-mismatch` shows the alert.

**I2. The `cover` query also matches ordinary phones in split screen and small desktop windows. The trade room then has no controls at all.**
- Code: `apps/web/src/ui/fold.ts:36`, `(max-width: 599px) and (max-height: 479px) and (max-aspect-ratio: 4/3)`.
- Probe: 412x430 (a Pixel in Android split-screen, top half) gave `data-fold=cover` and 0 visible controls. A 500x450 desktop browser window gave `cover`.
- It also fires when the layout viewport shrinks under the keyboard: Capacitor's Android WebView resizes the layout viewport by default (Plan 6 native wrapper), so a 360x640 phone with the keyboard open is about 360x360. Typing in a main-pane input switches to cover, which hides the focused input, so the keyboard closes and the layout flips back.
- Size alone cannot tell a Razr/Flip cover (about 424x360, 360x374) from a split-screen phone.
- Fix: never hide the main pane by size alone. Put the glance card first and keep the room reachable below it (or behind a "Show the trade" control), so a misdetection costs nothing. Add an e2e test at 412x430 that checks the room's primary action is reachable.

**I3. At 600–999 px without segments (iPad mini/Air portrait, Galaxy Tab, a narrow desktop window, the iPhone Fold), every sheet takes the left half of the screen, and its backdrop covers only that half.**
- Code: `apps/web/src/styles/fold.css:183-187` gives `.x2f-sheet-layer` `right: auto; width: var(--x2f-fold-a)` for every `data-fold='two'`, including screens that have no panes and span the full width (`fold.css:89` `grid-column: 1 / -1`, and all non-trade screens).
- Probe at 800x900: the dialog was 0..392 px and the backdrop 0..392 px, and `elementFromPoint(700,450)` hit live page content (the `ASIDE`) while the modal was open.
- On a non-pane screen (Quote, Wallets, Security confirm), the right half of the underlying page stays undimmed and clickable behind a modal that claims focus. For example, the Quote's "Trade" button can be pressed again while its confirm sheet is open.
- Fix: limit the half-width sheet to `.x2f-panes[data-side]` openers and to real segments (`@media (horizontal-viewport-segments: 2)`). Otherwise keep the full-width layer, or keep the backdrop full-width and only narrow the panel. Add an e2e test: a sheet on a non-pane screen at 800 px covers the whole viewport.

## Minor

- **M1. The layout-only CSS test is weak.** `apps/web/test/fold.test.tsx:151` only catches the shorthand properties: `\b(color|background|font|border|…)\s*:` does not match `background-color:`, `font-size:`, `border-radius:`, `border-color:`, `outline:`, `opacity:`, `fill:`, `line-height:` or `text-decoration:`. It also misses colour functions such as `oklch(`, `color-mix(` and named colours. Suggest `/(^|[\s;{])(color|background(-[a-z]+)?|font(-[a-z]+)?|border(-[a-z]+)*|box-shadow|outline(-[a-z]+)?|opacity|fill|stroke|text-(decoration|transform|shadow)|letter-spacing|line-height)\s*:/` plus `/\b(oklch|oklab|lab|lch|color-mix)\(/`.
- **M2. `trade.css:25` still keys the phone scroll body on `max-width: 999px`, not on the layout.** With segments at 1000 px or wider (a tri-fold's `three`, or a 1000x840 tabletop like the e2e board size), the room draws its phone layout without `.x2f-trade { height: 100dvh }`, so the primary action no longer stays pinned on screen. Suggest `:root:not([data-fold='wide'])`.
- **M3. The Chat sheet survives an unfold.** On a phone, BuyerPay's `ChatButton` sheet is open (`BuyerPay.tsx:341`). Unfold to `two`: the button is hidden by `[data-chat-link] { display: none }`, but its portalled Sheet stays open in the left pane while the side pane also mounts the chat. That gives two composers on one kept draft, and in the fixture two `#msg` ids. Suggest closing it when `chatPane` turns on (the room could pass a flag, or the button could close itself on `hasPanes`).
- **M4. Two-pane `paid` state has no visible primary action.** When BuyerPay's primary button *is* the Chat button, two-pane hides it, so the main pane has no `[data-primary]`. This is fine against Fold-Trade, but say so in the "exactly one `[data-primary]`" rule, or exempt it in parity.
- **M5. `useKeptText` is never cleared on log-out** (`fold.ts:94`, module Map). Low risk, since keys are per trade code, but on a shared tab a draft survives until reload. Suggest clearing it from the session's log-out path.
- **M6. Comment accuracy:** `fold.css`'s header says "no class is defined at the top level", but `.x2f-fold-glance*` and the unscoped `[data-shell='phone'] > [data-shell-body]` are top level. They are unique (css-collisions passes); just correct the comment.
