# X2F build roadmap

The approved spec (`docs/superpowers/specs/2026-10-14-x2f-design.md`) covers several independent subsystems, so it is built as six plans, in order. Each plan ends with working, tested software and its own security scan.

| # | Plan | Delivers | Status |
|---|---|---|---|
| 1 | **Foundation and escrow core** (`2026-10-15-plan-1-escrow-core.md`) | Monorepo with security gates; trade codes and fee maths; signed, encrypted protocol messages; the `EscrowEngine` (2-of-3 multisig with fee output, payout checks, save and resume); the message relay; every escrow outcome tested end to end on regtest | Built and approved (2026-10-17) |
| 2 | Accounts and login | Usernames; PGP challenge login; passkeys and security keys (WebAuthn); passwords (Argon2id, leaked-list check); TOTP; optional backup; "Your wallets" with confirm-it's-you and the opt-in 24-hour wait | Building: Tasks 1–9 done or in final review |
| 3 | Offers and the trade flow (web app) | Offer boards and posting; Trade; funding by `monero:` link or QR; I've paid, release, cancel, buyer no-show and auto-refund; trade chat; the screens built from the X2F App canvas; Playwright end-to-end tests at phone and desktop sizes | Building: Tasks 1–2, 7, 11, 13 in progress |
| 4 | Disputes and staff tools | Owner first-run setup; staff roles, invites and login hours; moderator dashboard and rulings with two-person approval; activity log; overview (emergency stop, earnings, banner, maintenance); performance and charts; training library | Draft, needs update for owner decisions |
| 5 | Reputation and safety extras | Reviews and blind reveal; profiles and badges; nudge; proof upload with metadata stripping and blur | Not written |
| 6 | Hardening and launch prep | Tor `.onion`; Capacitor iOS and Android apps with background resume; CSP and SRI; reproducible builds; external audit and penetration test | Not written |

## How every plan is executed (owner's instructions, 2026-10-15)

- **Many agents.** Subagent-driven: a fresh agent implements each task and a fresh reviewer checks it before the next starts.
- **agy agents take delegated tasks** through the agy MCP bridge. Their output is never merged unchecked: the security and review plugins check it first.
- **Security plugins check all code, whoever wrote it:** Semgrep and Security Guidance on every task; Claude Security on every finished plan; code-review plugins on each task's diff.
- **Claude Design is the source of truth for every screen** (X2F App canvas, X2F design system) from plan 3 onward.
