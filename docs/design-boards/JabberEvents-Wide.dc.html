Design notes

Showing: {{showing}}

Opens from the Events row of "Jabber alerts" on Alerts, once an address is set up. Built like JabberSetup: compact header, one primary card, then the info callouts. Each event is a list row (icon tile, title, what it covers, a switch) with the exact message under it in an inner block, so people see what they will get. A switch saves at once (the API sets one event per call), so there is no Save button; Done goes back to Alerts. Tweaks: account (trader or team owner) and state (set up or not set up).

Decided · owner, 9 Nov (p11-27) · lead, 12 Nov (W-021, review F1)The user picks which events send a Jabber message; security messages can't be turned off.
  • The events are the API's notice kinds: account changes, a trade that needs you, and (team owners only) a new team member's first login.
  • Account changes and a new team member are security notices: always on, shown with an "Always on" chip instead of a switch (review F1, until the owner rules on W-021's reach).
  • "A trade needs you" goes to the one who pays when a dispute opens on their trade (lead default, 8 Nov). On by default; the person can turn it off.
  • The team row shows only on a team owner's account: a trader without a team never sees it.
Decided · design, 12 Nov (J-20, review N3)A member joining sends one Jabber message, not two.
  • The join is the member's first login, so the lead gets only "A new team member logged in to your X2F account." The generic account-change message is not sent for the join itself.
  • Later changes to the member (role, trade-size band, hours, removal) send the account-change message as before.
Anticipated · design, 12 NovThis page replaces the "Sample list" of JabberSetup's events step.
  • The setup's events step shows these same rows once the owner signs the list (p11-32). New kinds join as new rows with their exact message.
  • Paused alerts (the switch on Alerts off) keep these choices.
