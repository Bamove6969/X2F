## Important

**I1. `apps/web/src/ui/cantDoCodes.ts:20`: `'only-login'` is not an API code. The real one is `last-login-method`, so that refusal never reaches CantDoThat.**
The API returns 409 `last-login-method` (`apps/api/src/auth/methods.ts:353`, `errors.ts:34`). `only-login` appears nowhere else in the tree. Failure: a user removes their only login method in Settings > Security, and `Methods.tsx:91` (and the client precheck at `:78`) shows `LAST_METHOD_MESSAGE` ("That is your only way to log in...") inline through `setError`. There is no popup and no feedback link, which breaks the owner's "EVERY popup that tells a user they can't do something". The lint does not catch it: the wording has no REFUSAL_WORDS term, and the literal `'last-login-method'` is not in CODES. Fix: replace `only-login` with `last-login-method` in CANT_DO_CODES. The lint then flags `Methods.tsx:91`, which has to move to CantDoThat (or take a `cant-do-that-todo`, which pushes the ratchet past 4, so that is the lead's call).

**I2. `tools/copy-lint.ts:161-165`: one import of `ui/CantDoThat` or `ui/cantDoCodes` exempts the whole file, so the rule cannot tell that a refusal really goes through the popup.**
Probed with `lintSource`: `import type { CantDoCode } from "../ui/cantDoCodes.js"` followed by `"Sorry, you're limited to 2 offers per side."` gives 0 findings, and so does a bare side-effect `import "../ui/CantDoThat.js"`. The five retrofitted files (PostOffer, offerForm, Wallets, Quote, takeErrors) are now permanently blind to the rule. Concrete case on the branch: `quote/takeErrors.ts:60` `already-waiting` ("You already have a trade on this offer waiting to be funded") is a rule refusal shown inline. The same goes for any refusal a later task adds to these screens, such as Plan 3's offer cap on PostOffer (the owner's own example, "Sorry, you're limited to 2 offers per side ..."). It would pass the lint even if it rendered inline. The plan's wording is "a component that shows a refusal without `CantDoThat` fails the check". Suggested fix: count a file as using the popup only when it renders `<CantDoThat` or calls one of the mapping helpers (`isCantDoCode`, `takeCantDo`, `postCantDo`). Even then, check refusal wording per piece. A text that is only the `body` passed to CantDoThat could carry the pragma, or come from a function whose name the lint knows. At least ignore `import type` and side-effect imports, and add a test case for each. Then either route `already-waiting` through CantDoThat or mark it.

**I3. `tools/copy-lint.ts:49`: REFUSAL_WORDS misses common refusal wording, including refusals already shown inline on the branch.**
The probe found 0 findings for each of: "unable to", "not able to", "couldn't", "only ... way", "once every 10 minutes", "already have", "maximum of", "must complete", "not permitted", "is blocked", "Too many", "isn't available". ## Minor

- **M1. Anonymity: insert order and the session touch** (`apps/api/src/feedback/form.ts:100,117`). The row stores only the day, but Postgres keeps insertion order: `xmin` (transaction id) and `ctid` (heap position) on a table that only ever grows by inserts. `requireSession` also writes `sessions.last_seen_at` with millisecond precision in the transaction just before the insert. Failure: someone with database access runs `select xmin, ctid, * from feedback_form` and compares the anonymous row's xmin with the xmin of timestamped rows nearby (trade_events, alerts, sessions). That puts the send within seconds, and `last_seen_at` or other activity at that moment names the sender. On a quiet day with one sender in the in-memory `sent` map, it is direct. `method_suggestions` (Task 3) has the same exposure, so it is precedent and not new. Cheap mitigations: `touch: false` on this route (the page loads already touched the session), and buffer anonymous rows in memory and flush them in random order once an hour. The UI copy `Feedback.tsx:126` "nobody at X2F knows it was you" promises more than that, so soften it ("is stored without your username") unless the fix lands. This is the lead's call.
- **M2. `form.ts:100` `allowHeld: true` breaks the `requireSession` contract** (`auth/sessions.ts:195`: "only routes that change nothing"). A held recovery session is exactly the one that may be an attacker using a stolen backup code. Failure: during the 24-hour hold, the attacker sends named feedback under the victim's account and uses up the victim's 5-a-day. The impact is low, but the rule needs a recorded exception or `allowHeld: false`. The test name says "takes a backup (recovery) session" but never tests a *held* one.
- **M3. `form.ts:115-121`: the daily count goes up before the insert.** If the insert fails (database down, 500), the account still loses one of its 5. Increment after the insert succeeds, or decrement in a `catch`.
- **M4. `form.ts:52-58` `listFeedbackForm` pages by day, but a page holds 50 rows.** Failure: a day has 80 rows. Page 1 returns 50 of them, and `before=<that day>` skips the other 30 for good. Use a `(created_on, id)` keyset cursor before the staff page wires this up (its tripwire is NEEDS_PLAN_4_STAFF).
- **M5. `form.ts:33` HIDDEN rejects every `\p{Cf}` and tab.** That includes ZWNJ U+200C (needed in Persian and other scripts) and ZWJ U+200D (emoji sequences such as family emoji or flags with tags). Failure: a Persian user, or a pasted tab or emoji ZWJ, gets 400, and the web client (`Feedback.tsx:71`) answers "That did not send. Try again in a moment." forever. Allow ZWNJ/ZWJ (and map tab to a space), or reject only the bidi controls (U+202A-202E, U+2066-2069) as chat does. And show a real message on 400.
- **M6. `Feedback.tsx`: a signed-out user learns they must log in only after typing and pressing Send, and the "Log in" link drops the typed text.** Keep a draft (as PostOffer does), or show the log-in line before the form when `useSession` is signed out.
- **M7. `Feedback.tsx:79`: after Send, the focused Send button unmounts and focus falls to `<body>`.** `role="status"` announces the text, but keyboard users lose their place. Focus the heading or the Done button.
- **M8. Pragma placement is loose** (`copy-lint.ts:167`). A `not-a-refusal:` anywhere on the line above, even inside a string literal, excuses the next line (probe: 0 findings). It also covers the whole line, so one comment can excuse several pieces. Accept the pragma only in a comment (the AST has comments, or require `//` / `{/*` before it). The 4-item `cant-do-that-todo` ratchet *is* enforced (`cantDoThat-lint.test.ts`, `≤ 4`, exactly 4 today), but `not-a-refusal` is unbounded and self-certified. List its uses in the review checklist or count them as well.
- **M9. Migration number.** The plan says `3xx_feedback_form.sql` (the Plan 5 range: 301-305 are already named in the plan). 114 is in Plan 3's "next free 1xx" range. It is unique today, but a later Plan 3 migration (flex offers says "next free 1xx") that picks 112 or 113 would run after 114 on an existing database and before it on a fresh one. Either renumber to 3xx or record the reason in coordination.md. Also: the e2e test title `feedback.spec.ts:78` says "a named send carries the refusal code", but it opens `/feedback` with no `from` and checks that no code is sent. Rename the test or add `?from=`.
